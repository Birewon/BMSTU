### Задание 1.

1. Для того что бы скомпилировать программу с возможностью использования в будущем отладчика необходимо компилировать ее с флагом `-g`. Если не использовать этот флаг при компиляции и потом попытаться отладить программу, то отладчик не сможет связать имена переменных с их адресами в памяти.
2. Для того что бы запустить программу под отладчиком необходимо воспользовать утилитой `gdb`. Для того что бы начать отладку необходимо прописать `run`, а что бы остановить программу `kill` .
3. Для просмотра значения переменной используется команда `print <variable>`, а что бы поменять значение переменной `set <variable> = <value>`.
4. Для того что бы выполнять программу в пошаговом режиме необходимо сначала поставить точку остановки программы с помощью `break` и после этого можно использовать такие команды как `step` - шаг с заходом внутрь функции, `next` - шаг без захода в функцию, `finish` - выход из текущей функции.
5. Чтобы узнать, какая цепочка вызовов привела программу к текущей точке останова, используется команда **`backtrace`**
6. `break <func/line/addr>`
7. Выключить - `disable <break_num>`. Включить - `enable <break_num>` . Пропустить количество срабатываний точки - `ignore <break_num> <count>` .
8. Задать условие можно при создании точки: `break <line_number> if <condition>`. Добавить условие точки остановки: `condition <break_num> <condition>`.
9. Для анализа памяти используется `x/nfu <addr>`. Где `n` - кол-во элементов для отображения, `f` - формат вывода, `u` - размер единицы памяти.

| Описания переменных | Представление в памяти (Hex) | Пояснение (почему получилось именно так) |
|---------------------|------------------------------|------------------------------------------|
| char c1 = 'a'; | 61 | Символ 'a' в таблице ASCII имеет десятичный код 97, что в шестнадцатеричной системе равно 0x61. Занимает 1 байт. |
| char c2 = -100; | 9c | Отрицательные числа хранятся в дополнительном коде. Для 8-битного char значение -100 вычисляется как 256 - 100 = 156 (0x9c в шестнадцатеричном виде). Занимает 1 байт. |
| int i1 = 5; | 05 00 00 00 | Число 5 типа int (4 байта) на архитектуре x86/x64 записывается в порядке Little-Endian (от младшего к старшему байту): 0x00000005. |
| int i2 = -5; | fb ff ff ff | Отрицательное число -5 в 4-байтовом int хранится в дополнительном коде (0xfffffffb). Из-за Little-Endian байты меняют порядок на противоположный. |
| unsigned u1 = 5; | 05 00 00 00 | Беззнаковое число 5 типа unsigned int (4 байта) записывается аналогично положительному int: 0x00000005, в памяти — от младшего байта. |
| long long ll1 = 5; | 05 00 00 00 00 00 00 00 | Число 5 типа long long занимает 8 байт (64 бита). Старшие байты заполнены нулями, младший байт содержит 5. |
| long long ll2 = -5; | fb ff ff ff ff ff ff ff | Отрицательное число -5 типа long long (8 байт) в дополнительном коде заполняется единицами (0xfffffffffffffffb) и записывается с младшего байта. |

### Задание 4.

| Описание элемента / операции | Представление в памяти (Hex) | Пояснение (почему получилось именно так) |
|------------------------------|------------------------------|------------------------------------------|
| int arr\[0\] = 1; | 01 00 00 00 | Первый элемент массива со значением 1 (тип int, 4 байта). На архитектуре Little-Endian байты записываются с младшего: 0x00000001. |
| int arr\[1\] = 2; | 02 00 00 00 | Второй элемент массива (значение 2) располагается в памяти сразу следом за первым (смещение ровно на 4 байта). Значение в Hex: 0x00000002. |
| int arr\[2\] = 3; | 03 00 00 00 | Третий элемент массива (значение 3) располагается на расстоянии еще 4 байт. Значение в Hex: 0x00000003. |
| ptr + 1 (арифметика) | Адрес увелич. на 4 байта | При сложении указателя на тип int с числом 1, адрес увеличивается не на 1 байт, а на sizeof(int) (на 4 байта), указывая точно на следующий элемент arr\[1\]. |
| ptr + 2 (арифметика) | Адрес увелич. на 8 байт | При сложении с числом 2 смещение составляет 2 \* 4 = 8 байт от базового адреса, указывая точно на элемент arr\[2\]. |
